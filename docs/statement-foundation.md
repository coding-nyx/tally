# Phase B statement and legacy-migration foundation

Status: **deployed and activated** after explicit approval of the activation proposal. The hub has migrations 0001–0004, Phase B enabled and **95 tools**. The source remains saved and uncommitted; deployment evidence is in [phase-b-deployment.md](phase-b-deployment.md). No real statements/browser records were uploaded, staged or migrated during this work.

## Implemented

- Persistent private CSV/selectable-text-PDF source bytes stored as PostgreSQL `bytea`, with SHA-256 verification on hydration and expiring authenticated downloads. Retention is bounded and append-only; source bytes are outside the web root and join the same transaction as metadata. Existing database dumps include them after activation. No new filesystem/blob service or credential is needed.
- Account/currency/period/opening/closing metadata, explicit start/end-of-day closing cutoff, parser identity (`tally-csv/1` / `tally-text-pdf/1`), original headers/cells, immutable mapping/correction revisions, row numbers, booking dates, full original descriptions and provider references.
- Exact observation replay identity is account + source-byte hash + row occurrence, plus a signature of its cells/parsed movement. Equal date/amount/merchant rows remain separate. Provider/date/amount candidates and provider-reference conflicts are review suggestions. No fuzzy match automatically merges or excludes a row.
- Frozen create/link/exclude decisions share the Phase A journal/approval/revision/idempotency/receipt/audit service. Multiple bank/card/transfer observations can reference one canonical journal, including later counterpart uploads and overlapping evidence. The chosen journal date and preserved source dates appear in review. Invalid rows must be corrected or explicitly excluded with a reason. Known-counterpart journals may be posted from one observation; the second observation can be linked later. Unknown counterparts stay unresolved by default; no clearing-account implementation was added.
- Correcting unreviewed source cells appends a revision and invalidates older plans through the workspace revision. Metadata/mapping revisions may preserve linked rows unchanged. A linked row's signed movement/cells cannot be silently rewritten; journal corrections use the existing reversal workflow.
- Live reconciliation compares closing observations against journals at the explicit cutoff. Missing openings/closings/mappings, unresolved/excluded rows, period journals lacking statement evidence and wrong statement openings stay visible. Approved reconciliation snapshots preserve history; later reads recompute current results. A discrepant close never creates a financial posting. Coverage reports show gaps and overlaps for the requested account/date interval. Balance reads carry latest dated source/reconciliation metadata.
- Shared legacy snapshot staging or explicitly uploaded browser-backup staging preserves untouched originals/settings/hash. Every row receives an explicit convert/cutoff/unassigned decision. Converted dates and amounts must match journal components; account/category/reclassification choices and reasons are frozen for review. Shared converted/cutoff rows leave legacy totals atomically with journals and mappings. Uploaded originals/settings/unassigned rows stay in their staged batch rather than being silently added to shared budget totals. Unassigned mappings can later be completed through append-only review history. Cutoff exclusion requires an existing reviewed opening and checks its start/end-of-day boundary. No opening is inferred.
- Owner Statements panel: selected-file staging, explicit mapping editor, source rows/match suggestions, decision editor, original legacy snapshot inspection, frozen source/journal review, approval/commit/cancel and coverage/discrepancy display. The panel now displays original cells before mapping, loads all source/match/legacy pages on request, rejects stale page continuation, and permits up to ten selected mapped statements in one grouped preview. The decision editor remains explicit; no automatic classification or approval was added.

## Schema and activation boundary

Currency/workspace/account/event/source foreign keys retain ownership. Previous statement and legacy-decision references preserve immutable revision chains. Runtime grants are SELECT/INSERT only for these tables. The store refuses rewriting/deleting previously stored evidence, and journals/receipts/source links commit together under the existing workspace lock.

The generated repository schema contains all 95 potential operations; discovery, not the static file, defines availability. Apply migration 0004 with the existing protected operator migration connection **before** enabling the flag. Builds/requests do not migrate automatically. Do not rerun provisioning or create replacement secrets.
